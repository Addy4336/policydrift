# PolicyDrift

PolicyDrift has two jobs:

1. **Research platform** for the paper *"Stale by Default: Measuring and Mitigating Outdated-Rule Answers in Multilingual Policy RAG Agents"*.
2. **Production-quality multilingual RAG agent** (English, Hindi, Gujarati) for Indian government rules. It answers with validated citations, shows which rule version and effective date it used, and flags conflicts.

**Research question:** when a government rule changes, does a RAG agent answer from the current retrieved rule, or from an outdated rule it memorised in training? Is this worse in Hindi and Gujarati than in English, and which mitigations fix it?

The hypotheses are recorded in [docs/preregistration.md](docs/preregistration.md). Related work and the novelty check are in [docs/related_work.md](docs/related_work.md).

## Hard rules

1. **The frozen test split is never used for tuning.** That includes prompt development, mitigation design, threshold choices, judge calibration and error analysis that feeds back into the system. Use the dev split for all of it. From Phase 2, the benchmark loader refuses to return the test split unless it gets an explicit `--final` flag. Do not bypass or weaken that guard.
2. **Every LLM call goes through the cached, rate-limited client** in `src/policydrift/llm/`. Never call a provider SDK directly. Identical requests must hit the cache, so no experiment spends quota twice.
3. **Official sources only.** Use only official government publications (central or state gazettes, ministry and department sites, scheme portals, official PDFs). Record every source in `data/SOURCES.md`, with its URL, a sha256 and the retrieval date.
4. **Hypotheses are frozen.** Do not edit H1–H3. The operationalisation in `docs/preregistration.md` is frozen before the first Phase 3 run on the test split. After that, every change goes in its dated deviation log.
5. **One phase at a time.** Finish the current phase, commit, and stop for the user's review before starting the next.
6. **Free tiers only:** Gemini and Groq free APIs, open-source embedding models, and the Supabase free tier. No paid services.

## Architecture (target)

Directories are created only when their phase starts.

```
policydrift/
├── docs/                 # related_work.md, preregistration.md, references.bib
├── data/
│   ├── SOURCES.md        # every official source: URL, version, effective dates, sha256, archive snapshot
│   ├── raw/<scheme>/<version>/   # original PDFs/HTML + manifest.json
│   ├── processed/chunks.jsonl    # each chunk: scheme, version, effective_from, effective_to, source_url, language
│   └── benchmark/{drafts,verification,dev,test}/   # test = frozen + checksummed
├── supabase/migrations/  # Postgres + pgvector schema
├── src/policydrift/
│   ├── llm/              # Gemini + Groq behind one interface; SQLite cache keyed by request hash, retries, rate limits
│   ├── ingest/           # fetch, parse, chunk, attach version metadata
│   ├── retrieval/        # multilingual open-source embeddings, pgvector store, version/date filters
│   ├── bench/            # LLM draft generation, CSV export/import for human verification, split + freeze
│   ├── agents/           # answerer, date-stamped prompting, conflict-checker agent
│   ├── experiments/      # YAML config schema (model, language, retrieval, mitigation, seed), runner, logging
│   ├── scoring/          # rule-based matcher (lakh/crore, Devanagari/Gujarati digits, dates), LLM judge, agreement
│   ├── citations/        # citation validation
│   ├── analysis/         # paired tests, confidence intervals, figures, tables
│   └── cli.py            # single entry point: `uv run policydrift <command>`
├── configs/              # models.yaml, experiments/*.yaml
├── runs/<run_id>/        # raw prompts, responses, model+version, timestamps, tokens (gitignored)
├── tests/                # retrieval, scoring, citation validation
├── paper/{figures,tables}/
├── api/                  # FastAPI, a thin layer over src/policydrift
└── web/                  # Next.js + TypeScript
```

The research pipeline and the demo backend share one Python package (`src/policydrift`). The API imports it and adds no research logic of its own.

## Commands

Commands use the `policydrift` CLI (Typer) through `uv run`, so they work the same on Windows and Unix. There is no Makefile.

| Command | Purpose | Available from |
|---|---|---|
| `uv sync` | Install pinned dependencies from `uv.lock` | Phase 1 |
| `uv run pytest` | Run tests | Phase 1 |
| `uv run ruff check . && uv run ruff format --check .` | Lint and format check | Phase 1 |
| `uv run mypy src` | Type check | Phase 1 |
| `uv run policydrift ingest ...` | Build the versioned document store | Phase 1 |
| `uv run policydrift bench ...` | Generate drafts, export/import verification CSVs, freeze splits | Phase 2 |
| `uv run policydrift run configs/experiments/<name>.yaml` | Run one experiment | Phase 3 |
| `uv run policydrift paper` | Regenerate every figure and table in `paper/` | Phase 5 |

## Conventions

- **Python 3.12** with **uv**: dependencies pinned in `uv.lock`, `src/` layout. Use type hints everywhere; `mypy` runs in strict mode on `src/`. Lint and format with `ruff`. Test with `pytest`.
- **TypeScript** in strict mode for `web/`.
- **Reproducibility:** every experiment is one YAML config and one command. Seeds are explicit in the config. Each run writes its config, git commit, model name and version, timestamps and token counts next to the raw outputs.
- **Languages:** use ISO codes `en`, `hi`, `gu` in data and configs.
- **Secrets:** keep API keys in `.env`, which is gitignored. List the variable names in `.env.example`. Never commit keys.
- **Commits:** use Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`, `test:`, `refactor:`), with one commit or more per milestone. There is no remote yet. Do not push or create one unless asked.
- **Citations in docs:** cite a paper only after opening its canonical page (arXiv, ACL Anthology, OpenReview or DOI), never from memory. Keep `docs/references.bib` in sync.
